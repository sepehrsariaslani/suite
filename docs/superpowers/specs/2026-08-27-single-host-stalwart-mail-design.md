# Single-Host Stalwart Mail Design

## Goal

Run a production Stalwart mail service for `dehati.ir` on the existing ERP host and manage it through Suite Mail without coupling its lifecycle to the ERPNext Docker stack.

The first mailbox will be `info@dehati.ir`. The existing website, ERP workloads, and their public HTTPS endpoint must remain available throughout the deployment.

## Current State

- The host public IPv4 address is `62.60.207.82`.
- `dehati.ir` and `mail.dehati.ir` currently resolve to that address.
- The current MX target is `dehati.ir`; it must be changed to `mail.dehati.ir` before production acceptance.
- The current PTR target is `82-207-60-62.static.hostiran.name`; the hosting provider must change it to `mail.dehati.ir`.
- Outbound TCP port 25 is reachable.
- Nginx owns public ports 80 and 443.
- SMTP, submission, IMAPS, and ManageSieve ports are currently unused.
- The root filesystem has approximately 12 GB free and is 91% utilized.
- Suite is installed on `dehati.ir`, but its Stalwart connection settings are not configured.

## Architecture

Stalwart runs in a dedicated Docker Compose project under `/etc/stalwart/mail.dehati.ir`. Its configuration and message data use persistent host directories owned by the container service account. The service is pinned to the Stalwart version expected by the installed Suite release rather than using a moving `latest` tag.

SMTP-related ports bind directly on the host. Stalwart HTTP/JMAP binds only to loopback on a high port. A dedicated Nginx virtual host terminates TLS for `mail.dehati.ir` and proxies JMAP, discovery, account, and administration requests to that loopback listener. This avoids conflict with the existing Nginx listener on port 443.

Suite Mail connects to the public `https://mail.dehati.ir` endpoint and uses a generated Stalwart administrator credential stored as a Frappe password field. Recovery credentials remain in a root-readable environment file and are never committed.

## Network Exposure

The deployment exposes only these listeners:

| Port | Protocol | Purpose |
|---:|---|---|
| 25 | SMTP | Server-to-server inbound and outbound mail |
| 465 | SMTPS | Authenticated client submission over implicit TLS |
| 587 | Submission | Authenticated client submission with STARTTLS |
| 993 | IMAPS | Encrypted IMAP client access |
| 4190 | ManageSieve | Optional client-side filtering rules |
| 443 | HTTPS/JMAP | Served through the existing Nginx process |

Unencrypted IMAP and POP3 listeners are not exposed. Stalwart's recovery and internal HTTP listener binds to `127.0.0.1` only.

## DNS And Identity

The production DNS state must be:

- `A mail.dehati.ir -> 62.60.207.82`
- `MX dehati.ir -> mail.dehati.ir` with priority 10
- `PTR 62.60.207.82 -> mail.dehati.ir`
- Forward-confirmed reverse DNS: `mail.dehati.ir -> 62.60.207.82`
- One SPF TXT record authorizing this server
- Stalwart-generated DKIM TXT records
- A DMARC TXT record initially using monitoring policy `p=none`, upgraded only after reports verify alignment
- Client discovery and transport-security records generated by Stalwart where supported

The `mail` host must resolve directly to the server and must not pass through an HTTP proxy. Existing website records remain unchanged.

## Storage And Quotas

The initial mailbox quota is 2 GB. Registration is disabled, so only administrators can create mailboxes. Stalwart data is kept separate from ERP database data, but it remains on the same filesystem for this deployment.

Installation may proceed with the current free space because the initial quota is bounded, but production acceptance requires a disk alert at 85% and a documented expansion or cleanup action. The mail service must stop accepting new local message data before exhaustion can affect MariaDB or ERPNext.

Backups include Stalwart configuration, metadata, signing material, and message data. Backup output must not be stored only on the same filesystem as the live mail store.

## Provisioning

Deployment is idempotent and consists of:

1. Generate non-committed recovery and administrator credentials.
2. Create persistent Stalwart directories and a standalone Compose definition.
3. Start Stalwart on loopback HTTP and direct mail ports.
4. Validate health and inspect logs before changing Nginx or DNS.
5. Obtain a trusted certificate for `mail.dehati.ir` through the existing Certbot/Nginx setup.
6. Add and validate the Nginx virtual host.
7. Configure Suite Mail with the public server URL, root domain, SSL verification, and encrypted administrator password.
8. Create the `dehati.ir` domain and `info@dehati.ir` mailbox with a 2 GB quota.
9. Export the exact DNS records generated by Stalwart and apply them in HostIran DNS.
10. Test authenticated submission, inbound SMTP, JMAP, IMAP, DKIM, SPF, DMARC, TLS, and Suite Mail UI access.

## Credentials

All passwords are generated with cryptographically secure randomness. The temporary `info@dehati.ir` password is shown once to the administrator and must be changed after the first successful login. Secrets are excluded from Git, shell history where practical, command output, and user-facing logs.

## Failure Handling And Rollback

The ERP stack is not modified during the initial Stalwart startup. Nginx configuration is tested before reload. If HTTPS/JMAP validation fails, the new virtual host is removed and Nginx is reloaded without stopping ERP services.

DNS MX changes occur only after local SMTP and TLS checks pass. If external delivery fails after the MX change, the MX record can be returned to its previous value while Stalwart remains isolated for diagnosis. Container removal never removes persistent mail data unless a separate, explicit data-deletion step is approved.

## Acceptance Criteria

- `dehati.ir` and its ERP APIs remain healthy during and after deployment.
- `https://mail.dehati.ir` presents a trusted certificate and exposes valid JMAP discovery.
- Suite Mail can authenticate and open the mailbox for `info@dehati.ir`.
- An authenticated message sent from `info@dehati.ir` reaches an external mailbox with SPF and DKIM passing.
- A reply from an external mailbox appears in Suite Mail.
- PTR and forward DNS match `mail.dehati.ir`.
- DMARC exists and reports alignment without enforcing rejection during the initial observation period.
- Restarting the standalone Compose project preserves the mailbox and messages.
- Disk usage and Stalwart container health are observable without exposing administrative ports publicly.

## Out Of Scope

- High availability or a second MX server
- Migrating mail from another provider
- Unlimited mailbox creation or public signup
- Marketing or bulk-email delivery
- Storing backups permanently on the same host
